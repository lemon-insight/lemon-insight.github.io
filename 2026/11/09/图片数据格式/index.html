计算机系统内的图片数据格式

Lemon 柠檬 Lv2

从手机相册到网页加载，图片在计算机里始终以“像素数据 + 编码规则”的形式存在。不同格式的差异，本质上是在画质、体积、兼容性与可编辑性之间做取舍。选对格式，往往比单纯调高压缩参数更能兼顾观感与成本。本文梳理主流图片格式的分类逻辑、核心特征与选型方法。

一、图片格式的分类逻辑

按数据的组织方式，图片格式可分为四条主线：位图（栅格）用像素矩阵记录颜色，是照片和截图的基础；矢量用几何路径和文本描述图形，与分辨率无关；动画/多帧在单帧图像上叠加时间维度；程序内部原始像素则连文件容器都省去，直接把内存中的像素数组交给后续计算。

位图内部再按压缩方式细分：无压缩（BMP）、无损压缩（PNG、GIF、TIFF 无损）、有损压缩（JPEG、WebP/AVIF 有损）。透明、动画、色深与色彩空间、可编辑性，共同划定了格式的适用边界。

二、主流格式逐一详解

BMP：Windows 原生位图，按行存储像素，基本不压缩（可选 RLE）。支持 1/4/8/16/24/32 位，24 位真彩最常见；32 位可带 Alpha，但兼容性依赖具体实现。体积巨大，几乎没有色彩管理和元数据能力，适合教学演示、嵌入式屏显和简单图标。

JPEG：把图像分块做 DCT 变换、量化和熵编码，属于有损压缩，质量因子越低体积越小，块效应和振铃也越明显。8 位色深，常配合 4:2:0 色度抽样；不支持透明和动画。渐进式 JPEG 可先粗后细加载，EXIF 可保存拍摄参数。照片压缩效率高，但文字和线条边缘容易发糊，不适合反复编辑保存。

PNG：先做行预测滤波，再用 DEFLATE 无损压缩。支持灰度、调色板、RGB/RGBA，色深 1–16 位，拥有完整的 Alpha 透明通道。适合截图、界面、线条图和带透明背景的素材；照片体积通常远大于 JPEG。它可嵌入 ICC 色彩配置。APNG 可做动图，但生态一般。

GIF：基于 LZW 无损压缩，8 位索引色最多 256 色，支持 1 位透明和帧动画。兼容性极好，但调色板限制了色彩数量，渐变易出现色带，体积也偏大。它适合表情包和简单循环动图，正逐步被 WebP、APNG 和视频取代。

WebP：Google 推出，分 VP8 有损和 VP8L 无损两种模式，支持 Alpha、动画和 24 位色。同画质下通常比 JPEG 小 25%–35%，无损模式比 PNG 小约 20%–30%，现代浏览器已普遍支持。它还支持“有损 + Alpha”组合，常用于带透明阴影的商品图和界面素材。

AVIF：基于 AV1 帧内编码的开放标准，支持有损与无损、10/12 位色深、HDR、广色域、Alpha 和动画。同等主观画质下常比 JPEG 小约一半，压缩率通常优于 WebP；但编码慢、旧设备和旧软件支持不足，适合现代 Web 的高质量图片分发。

SVG：基于 XML 的矢量格式，用路径、形状和文本描述图形，缩放不失真，可被 CSS 和 JavaScript 控制，文本可搜索。图标、Logo、图表和简单插画的首选；若引用外部字体，交付前应转曲或嵌入，避免不同设备渲染不一致。照片和复杂纹理会让路径数量激增，不适合。

TIFF：标签化容器，可存多页、多图层，支持未压缩和 LZW/ZIP/Deflate 无损压缩，8/16 位、RGB/CMYK/灰度、Alpha 均可。标准 TIFF 单文件上限约 4 GB，超大图可用 BigTIFF。它体积大但保真度高，是印刷、扫描、医学影像和存档母版的常用格式，不适合直接用于网页。

RAW：相机传感器的原始数据，通常为 12/14/16 位，未去马赛克，白平衡、锐化等参数尚未固化，后期调整空间大。各品牌格式私有（CR2、NEF、ARW 等），也有开放的 DNG。它更像“数字底片”，是后期流程的起点，而不是可直接分享的成品。

延伸格式速查

格式 类型/压缩 关键特征与用途
JPEG XL 有损/无损 可无损转码已有 JPEG，支持 HDR 与渐进解码，生态仍在推广
HEIC/HEIF 有损（HEVC） 苹果设备默认照片格式，体积小，跨平台兼容性一般
ICO/CUR 位图多尺寸 单文件内含多种尺寸，网站图标与 Windows 光标
TGA 可选 RLE 结构简单、支持 Alpha，游戏纹理与中间格式
PSD 无损分层 Photoshop 工程文件，保留图层、蒙版与调整
DDS 块压缩（BCn） GPU 可直接采样，游戏引擎纹理常用
Netpbm 无压缩/简单 PPM/PGM/PBM，图像处理算法的中间格式
HDR/EXR 浮点 高动态范围与浮点像素，渲染与影视后期
PDF/EPS/AI 矢量/页面描述 印刷、文档交换与设计源文件，AI 兼容 PDF
EMF/WMF/CDR 矢量 Windows 图元文件与 CorelDRAW 工程文件

动画与程序内部数据

动画方面，GIF、APNG、动画 WebP/AVIF 各有取舍；长动画通常直接用 MP4/WebM 视频容器，游戏则常用序列帧或精灵图。

若程序内部只需保存原始像素，未必需要图片文件：width × height × channels 的 uint8/float32 缓冲区最直接；NumPy 的 .npy/.npz、HDF5 适合多维科学影像；base64 Data URI 可把图片嵌进 HTML/JSON；自定义头部加裸像素则追求读写速度。

三、场景化选型建议

场景 首选 备选与说明
网页照片 AVIF WebP、JPEG，用 <picture> 做回退
网页图标/插画 SVG 复杂位图用 WebP 无损
截图/透明素材 PNG WebP 无损，体积更小
动效/表情 WebP 动画 GIF（兼容优先）、APNG；长动画用视频
摄影后期 RAW 16 位 TIFF/PSD 作中间文件
专业印刷 TIFF/PDF（CMYK） 高质量 JPEG 可用于照片
存档备份 RAW + 无损 TIFF/PNG 保留原件，避免有损反复转码
苹果设备照片 HEIC 分享或跨平台时转 JPEG/AVIF
游戏纹理 DDS/KTX 使用 GPU 压缩格式，避免运行时解码
影视渲染 EXR/HDR 保留浮点动态范围与高光细节
程序内部交换 NumPy/HDF5 保存原始像素数组，避免有损转码

补充原则：网页优先按“AVIF → WebP → JPEG/PNG”做渐进增强；办公与邮件优先 JPEG/PNG，保证通用兼容；设计交付区分源文件和导出文件；印刷链路尽量使用 CMYK 与 300 ppi；存档优先选择开放、无损、文档齐全的格式。

四、选型决策维度总结

选格式时按顺序问自己几个问题：

  1. 内容类型：连续色调照片，还是线条、文字、图标？
  2. 透明与动画：是否需要 Alpha 通道或逐帧动画？
  3. 画质要求：能否接受有损压缩，是否需要 HDR、广色域或高位深？
  4. 体积与带宽：面向网络分发还是本地保存？
  5. 兼容性：目标浏览器、系统、印刷厂、相册软件是否支持？
  6. 可编辑性：是否需要反复修改、分层、保留原始信息？
  7. 长期可读性：格式是否开放、解码器是否长期可得？

总结：照片分发看压缩效率，图形界面看无损与透明，设计源文件看可编辑性，印刷与存档看色深、色彩空间和保真度，动效看兼容性与体积的平衡。归根结底只需确认三件事：有损还是无损、是否支持透明或动画、位深与色彩空间是否满足下游流程；另外 .jpg 与 .jpeg 只是扩展名不同，格式完全一致。
