计算机系统内常见的压缩格式及压缩原理

Lemon 柠檬 Lv2

存储、传输和备份都离不开压缩。但“压缩”常被和“打包”混为一谈：tar 只是把多个文件装进一个容器，gzip 才是把数据变短；zip、7z 则两者兼有。

一、先分清归档与压缩

归档把多个文件合成一个容器，本身不一定压缩，例如 tar、ISO；压缩按算法把数据变短，例如 gzip、xz 的单条数据流。Linux 上常见的 tar.gz 就是分工合作：tar 负责打包，gzip 负责压缩这一条流。

压缩又分两类：无损压缩解压后与原文逐位相同，适合程序、文本、数据库等通用数据；有损压缩允许人感知不到的失真，主要面向图像、音频和视频。注意，JPEG、MP4、DOCX 等内部已是压缩数据，再塞进 zip 几乎压不动，甚至可能变大。

二、无损压缩的核心原理

无损压缩本质只做两件事：消除冗余，以及用熵编码把高频符号写得更短。

1. 熵编码

Huffman 编码统计符号频率，构造最优前缀码：高频符号用短码，低频用长码，任何码都不是另一个码的前缀，因此可唯一解码。它的局限是每个符号至少占 1 bit，码长必须是整数位，压缩率有上限。

算术编码、区间编码和 rANS 不再给单个符号分配整数位，而是把整个序列映射到 [0,1) 区间中的一个小数，用区间边界表示。它能更逼近信息熵，常见于 LZMA、JPEG 2000 以及部分现代编码器。

2. RLE 与字典编码

RLE（游程编码） 把连续 N 个相同值记成“值 + 次数”，适合图标、传真、扫描件和大片空白，PNG 滤波、BMP 的 RLE 都用到它。

LZ77 在已输出的历史窗口里寻找最长匹配，输出“回溯距离 + 匹配长度 + 下一个字符”；LZ78 增量构建短语字典；LZW 是 LZ78 的工程化变体，边压边建字典，解码端同步重建，不需要传输字典，GIF 和 TIFF 常用。LZ 系列自身输出仍是距离、长度和字面量，通常再套一层 Huffman 或算术编码，这才是强压缩的关键。

3. BWT 与上下文建模

BWT 是可逆排列：把所有循环移位排序后取最后一列，能把相似上下文聚到一起，再配合 MTF、RLE 和熵编码，bzip2 就是这套组合。上下文建模（如 PPM、CM）根据前几个字节预测下一个字节的概率分布，再用算术编码，压缩率极高但速度慢，7-Zip 的 PPMd 以及 PAQ 系列都属于此类。

三、有损压缩的核心原理

有损压缩通常由“变换 + 量化 + 熵编码”组成。变换把信号从像素或采样域转到频域，例如 JPEG 的 8×8 DCT、音频的 MDCT；量化按感知重要性丢弃系数，是画质或音质损失的主要来源；最后再对剩余系数做熵编码。音频利用心理声学掩蔽效应，图像和视频利用视觉掩蔽与色度下采样。视频还会做帧间运动补偿，只编码运动矢量和残差，压缩率主要来自相邻帧的高度相似。

四、常见压缩格式

通用无损压缩

格式 扩展名 核心算法 特点
ZIP .zip DEFLATE（LZ77 + Huffman） 最通用，可单独解出成员，支持加密
GZIP .gz DEFLATE 单流、无归档、不能随机访问，HTTP 常用
BZIP2 .bz2 BWT + MTF + RLE + Huffman 压缩率高于 gzip，慢、内存大
XZ .xz LZMA2（LZ77 + 区间编码） 压缩率很高，压缩慢、内存需求大
7z .7z LZMA/LZMA2、PPMd 等 容器 + 多算法 + 固实压缩
RAR .rar 私有 LZ + PPM 变体 商业格式，固实、恢复记录、分卷强
Zstandard .zst LZ77 + FSE + Huffman 速度与压缩比平衡极佳，支持字典
Brotli .br LZ77 + 上下文建模 + 静态字典 Web 文本优化，HTTP Content-Encoding: br
LZ4 .lz4 极简 LZ77 解压可达 GB/s 级，压缩比一般
Snappy — LZ77 简化版 快而稳定，大数据组件常用
LZOP .lzo LZO 解压极快，嵌入式与内核常用

ZIP 与 7z：随机访问与固实压缩

ZIP 的中央目录记录每个成员的位置，解压单个文件只需定位目标成员，随机访问好；但每个文件独立压缩，字典逐文件重置，跨文件重复无法利用，压缩率偏低。标准 ZIP 没有固实模式。

7z 默认固实压缩，把多个文件连成一块统一压缩，字典可跨文件复用，小文件多时压缩率更高。但固实块是连续流，取块内文件必须从块首解压到目标位置，随机访问差；改一个文件通常要重压整块，损坏也可能波及后续文件。可用 -ms=off 关闭固实，或用 -ms=100m 控制块大小，在压缩率与随机访问间折中。

频繁取单个文件选 ZIP 或非固实 7z；追求体积、整体归档选固实 7z；RAR 逻辑类似。

图像、音频与视频

图像方面：PNG 用行滤波加 DEFLATE 无损压缩；GIF 用 LZW 和 256 色调色板；JPEG 走 YCbCr 转换、色度下采样、DCT、量化和 Huffman；WebP 有损基于 VP8 帧内编码，无损用预测加 LZ77；AVIF 和 HEIC 分别基于 AV1、HEVC 帧内编码；JPEG XL 兼顾无损与有损；TIFF 是容器，可装 LZW、DEFLATE 或 JPEG；RAW 保存传感器原始数据，常用预测加熵编码。

音频方面：FLAC 和 ALAC 用线性预测加 Rice 编码实现无损，文件约为 WAV 的 50%–70%；MP3、AAC 依赖心理声学模型和 MDCT；Opus 结合 SILK 与 CELT，低延迟、低码率表现好；Vorbis 是开源的有损方案。

视频方面：H.264、HEVC、AV1、VP9 都采用帧内预测、运动补偿、变换、量化和熵编码，压缩率主要来自时间冗余；ProRes、DNxHD 是帧内低压缩编码，追求剪辑流畅而不是最小体积。

容器与编码不是一回事

.mp4、.mkv、.webm 是容器，里面可以装 H.264、AV1、AAC 等编码流；.docx、.xlsx、.epub、.jar、.apk 本质上都是 zip 容器。判断一个文件“是什么压缩”，要先看容器，再看它使用的编码。

五、容易混淆的几个点

  1. gzip 不能打包多个文件，它只压一条流；多文件要先 tar，tar.gz 就是先打包再压缩。
  2. ZIP 能随机访问，每个成员独立压缩，可单独解出；tar.gz、xz 是流式，取一个文件往往要从头解。
  3. 压缩率不是唯一指标，还要看压缩与解压速度、内存、随机访问、多线程和可恢复性，这正是 zstd、LZ4 存在的原因。
  4. 加密不是压缩，ZIP 的 ZipCrypto 很弱，敏感数据应使用 AES-256。
  5. 已经压过的数据别再压，JPEG、MP4、多数 PDF 和压缩包再压基本无收益。

六、场景化选择

场景 推荐
跨平台分享、需要单独取文件 ZIP
Linux 备份与打包 tar + zstd（快）或 tar + xz（小）
追求最小体积、不急着解压 7z（LZMA2）或 XZ
日志、数据库、实时传输 Zstandard 或 LZ4
Web 静态资源 Brotli，gzip 兜底
长期冷存储 zstd –long 或 XZ，配合校验和
图片 照片用 JPEG/HEIC/AVIF，截图图标用 PNG 或 WebP 无损
音频 归档用 FLAC，便携用 AAC/Opus
视频 分发用 H.264/HEVC/AV1，剪辑用 ProRes

七、总结

归档格式负责“装”，压缩算法负责“减”；无损压缩靠“找重复 + 熵编码”，有损压缩靠“丢掉人感知不到的信息”。实际格式几乎都是多种技术的组合：ZIP 是 LZ77 + Huffman，XZ 是 LZ77 + 区间编码，JPEG 是 DCT + 量化 + Huffman。
