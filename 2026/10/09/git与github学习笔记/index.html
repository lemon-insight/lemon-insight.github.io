Git 与 GitHub 学习笔记

参考 B 站「马克的技术工作坊」的教程《一个视频学会 Git + GitHub》整理，示例项目：MarkTodo。

一、Git 和 GitHub 是什么

  • Git：分布式版本控制系统，给每次改动打「存档点」，可随时回滚。
  • GitHub：基于 Git 的代码托管平台，负责云端备份与协作。

二、安装与配置

  • Windows：官网 git-scm.com 下载安装，默认即可。留意两个选项：勾选「加入 PATH」、换行符选 Windows 风格；安装路径建议纯英文。
  • macOS：brew install git

四、回滚的三种场景

回滚方式取决于改动走到了哪一步。

场景一：还没 add

场景二：已 add，还没 commit

场景三：已 commit

模式 效果 适用场景
--soft 只撤销 commit，改动留在暂存区 重新组织提交
--mixed（默认） 撤销 commit 和 add，改动留在工作区 重新挑选提交内容
--hard 三处全部丢弃 彻底放弃改动

黄金法则：已推送到远程的提交，用 git revert 生成反向提交来抵消，不要 reset 改写历史。

五、.gitignore：忽略文件

编译产物、日志、密钥等不该进仓库，在仓库根目录创建 .gitignore：

两个坑：

  1. .gitignore 只对未跟踪的文件生效。已被跟踪的文件要先 git rm --cached 文件名 移出版本库（本地文件保留）。
  2. 规则不生效时，用 git check-ignore -v 文件名 排查。

六、分支与合并

分支本质是指向某次提交的指针，创建几乎零成本：

两种合并策略（git switch main 后 git merge feature）：

  • Fast-forward：主线分叉后无新提交，指针直接前移，历史为直线；
  • 三方合并：两边都有新提交，产生一个合并提交；想保留合并痕迹可用 --no-ff。

七、进阶：Rebase、Stash、Worktree

Rebase：git rebase main 把当前分支的提交摘下来，重新安放到 main 最新提交之后，历史变成一条直线。代价是提交被改写（新哈希）。铁律：只对未推送的本地提交做 rebase。

九、命令速查表

场景 命令
查看状态 git status / git diff / git log --oneline --graph
存档 git add . → git commit -m "说明"
丢弃工作区改动 git restore 文件名
取消暂存 git restore --staged 文件名
撤销提交 git reset --soft/--mixed/--hard HEAD~1
分支 git switch -c 新分支 / git merge 分支 / git branch -d 分支
收起现场 git stash / git stash pop
整理历史 git rebase main（仅限未推送提交）
并行开发 git worktree add ../目录 分支
远程同步 git push / git pull / git clone 地址

十、结语

学完下来最大的感受是：Git 的日常其实就一个循环——改代码 → add → commit → push。剩下的命令大多是出错时的「后悔药」和历史整理工具，用到时查一下就行，不必刻意去背。

不过有三类东西值得亲手练一遍：三种回滚场景、合并冲突，以及分支的基本操作。看懂和会做是两回事，拿个小项目把坑踩一遍，比看十篇文章都管用。
